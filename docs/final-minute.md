# Final-minute research view

BTC, ETH and SOL each use their existing shared CF Benchmarks WebSocket: BRTI, ETHUSD_RTI and SOLUSD_RTI. Kalshi's public active-market response supplies the numeric floor_strike target, strike_type, ticker and open/close times. Only the matching asset's active 900-second market with a positive greater_or_equal target supports a distance calculation. Metadata is refreshed by existing snapshot requests; after 45 seconds without a valid refresh the panel marks it stale.

The Rust recorder receives valid ticks before the watch channel combines browser updates. It keeps at most roughly 183 source-second buckets in memory per asset, retaining the newest source timestamp in each second. Invalid prices, timestamps over 10 seconds old or over two seconds ahead are rejected before advancing the feed timestamp marker. The buffer is not a durable recording and does not guarantee continuous collection when Cloud Run is idle, restarts, disconnects or throttles background CPU.

For close time C, the final window is [C−60 seconds, C). The average uses the latest received value within each **completed** source second, weighted equally. The still-open second and values at/after C are excluded. Missing seconds are omitted, never forward-filled. The UI separately reports observed/elapsed seconds and observed/60 full-minute coverage. A 60-cell strip distinguishes observations, elapsed gaps and not-yet-completed seconds as of the server response. It is not retroactively filled from historical candles.

The displayed average is our observation statistic, not Kalshi's official settlement value, guarantee, outcome or forecast. Source timing, gaps, later revisions, rounding and official methodology can differ. The individual contract rules govern. See https://help.kalshi.com/en/articles/13823838-crypto-markets .

Latest index minus target is the signed USD distance; percentage distance is 100 × distance / target. Distance hides after a stale/disconnected reference, stale market metadata or close. The countdown uses server time plus elapsed browser monotonic time, avoiding dependence on the user's wall-clock setting. Source age and coverage update time remain visible. Asset changes clear old presentation state; late messages from the prior asset are ignored. A new market's averaging window cannot include the previous market's seconds.

Delivery reuses reference.final_minute inside /api/feeds and the local /api/reference SSE envelope. It adds no Kalshi requests, credential scopes, write endpoints, database operations, services or background workers. Existing quarter-CPU, memory, maximum-one-instance and traffic controls remain. Slightly larger feed replies consume existing outbound capacity; the $40 budget remains an alert target rather than a guaranteed invoice ceiling.

Validation: Rust tests cover second boundaries, equal weighting, duplicate and out-of-order samples, late joining, gaps, expiry exclusion, rollover, stale/future timestamps, invalid targets, asset isolation and bounded memory. A local WebSocket test ensures a future timestamp cannot block a subsequent valid tick. Browser tests cover source staleness, clock transitions, coverage preservation and late messages after switching/leaving. Local desktop and 390px mobile checks confirm clear disabled/gap states, no horizontal overflow and no script errors.

## Remaining-average threshold

During the final minute, the server computes (60 × target − the unrounded sum of completed source-second observations) ÷ (60 − elapsed seconds). It requires a valid at-or-above target, fresh live reference data, fresh market metadata and an observation in every elapsed second. It excludes the still-open second. Any elapsed gap suppresses the indicator. A nonpositive requirement is displayed as “Any positive average” within this observation model.

The displayed price rounds upward to the asset’s usual USD precision, so rounding cannot lower the displayed requirement. The remaining-second count and timestamp refer to the same server summary. The browser suppresses the value after three seconds without a summary, stale/disconnected source data, market rollover or close. The client never advances the sum from a countdown alone.

For a $100 target and 40 completed observations averaging $100.10, the remaining 20 observations need to average at least $99.80. The indicator describes our equal-weight, latest-observation-per-second mean. Official sampling, revisions, settlement rounding and contract rules can differ. It does not assert a guaranteed YES result.
