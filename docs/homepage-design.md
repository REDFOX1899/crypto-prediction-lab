# A homepage for the quarter-hour research desk

9 November 2026. The public application has three views: Home, Single market and Combo lab. Home is the default at /. Existing ?asset=BTC/ETH/SOL URLs keep opening the market workspace; explicit ?view=market&asset=SOL links and ?view=combos remain supported. Browser back/forward selects the correct view. Inactive workspaces close their subscriptions and stop refresh timers.

The homepage explains the actual implemented product: read-only BTC/ETH/SOL 15-minute market research. It includes an original quarter-hour observatory illustration, a shared-window countdown, current targets and YES/NO ask snapshots, aggregate visible bid-size shares, and twelve fixed recent outcome slots per asset. Live quotes and top-ten book-size shares now use the existing shared /api/feeds response every two seconds (fifteen seconds when hidden). Target/window snapshots refresh every thirty seconds (forty-five seconds when hidden), with a refresh scheduled at expiry and a five-second retry when no active market is found. History refresh is sixty seconds (three minutes when hidden). No extra upstream Kalshi WebSocket is opened by Home. It reuses the existing live feed, public snapshot and archive endpoints. No new account, data-write API, AI inference API, RFQ permission, cloud service or payment feature is added.

The clock requires three active markets with equal opening/closing times and exactly 900-second duration. Missing or stale market discovery hides the countdown. Visible depth uses positive quantities at valid bid prices and is explicitly not an outcome probability. Unavailable archive slots remain neutral rather than being converted into losses. Source failures are labeled while any previous displayed values remain marked as previous data. Home is a starting point; the detailed chart and permanently expanded single-market order book remain in their existing workspace.

Generation happens once during design, not per visitor. There is no OpenAI API key in the site and no recurring image-generation request. The compressed asset fits the existing 1 MiB response/burst limits. Existing quarter-CPU, zero-minimum/one-maximum-instance hosting and budget alerts remain unchanged. Extra bandwidth and homepage snapshot/history requests still count toward normal usage; the previously documented $40 ceiling remains an estimate/alert, not an enforced billing cap.

## Shared live homepage delivery — 9 November 2026

Home subscribes to BTC, ETH and SOL through three DashboardFeed listeners sharing one all-asset HTTP request every two seconds. It does not fetch three snapshots every two seconds. Fresh matching books supply YES ask = 1 − best NO bid and NO ask = 1 − best YES bid; a fresh matching ticker can provide the fallback live quote. Empty sides stay unavailable. Depth shares consistently use the ten best valid levels on each side, and the label distinguishes live depth from a snapshot. Prices remain indicative and exclude fees.

A per-card LIVE badge requires an active, matching 900-second contract, recent metadata, a feed response received within eight seconds and quote/book data no older than fifteen seconds. Snapshot fallback, stale metadata and connecting states have different badges. Source ages remain visible. Targets are explicitly fixed for the current contract. Actual price changes receive a brief colored highlight; the pulse and highlights respect reduced-motion preferences.

Polling is single-flight, has an eight-second timeout, respects numeric Retry-After responses and backs off after failures. Hidden tabs slow to fifteen seconds and resume promptly when visible. Closing the last subscriber aborts its request, and a late reply cannot be delivered to a new workspace. A failing subscriber cannot interrupt other cards. Home cancels pending metadata/history requests on leave and ignores earlier generations. Repeated unchanged historical grids and text do not rebuild. The inactive Single Market view skips its freshness/countdown DOM updates.

The normal visible target refresh rate falls from three requests every twenty seconds to three every thirty seconds, while live values are delivered from shared in-memory state. This reduces those target snapshot requests by roughly one-third. Total homepage requests increase because it now receives live updates; no new provider subscription, paid API or cloud resource is introduced. Existing pilot CPU, memory, request and outbound controls remain. They can impose temporary backoff under load; the $40 budget alert remains a target, not a guaranteed bill ceiling.

Validation includes 33 Rust tests and 29 JavaScript tests, formatting and clippy, card source/expiry matching, empty-book handling, stale data, retry cooldown through visibility changes, aborted requests and late responses, preserving live quotes through snapshot refresh, and browser layout/navigation checks.
